## 2026-10-08 — Master task: complete and correct the broken-grain analysis

### Task
Make Whole-vs-Broken analysis correct, scale-safe, reference-safe, and properly reported
across arbitrary images. Focus: reference determination, calibration-aware measurement,
all-broken handling, UI/report semantics.

### Actual root cause
The previous B13 report was too narrow. B13 segmentation was already correct (12/12).
The actual unresolved problem was reference determination semantics:
- The 154.1 px default_rice.json profile was being treated as "reliable" merely because
  it loaded successfully, even though it is explicitly a scale-specific proxy.
- No clear separation existed between physical/mm profiles (production eligible),
  legacy pixel profiles (proxy/demo only), and sample-derived references.
- All-broken images without an explicit profile were not being handled as undetermined
  with a clear explanation.
- The UI did not accurately distinguish classified vs undetermined states.

### Reference hierarchy implemented
1. Explicit calibrated physical profile (mm) + valid calibration -> production eligible
2. Sample-derived whole-kernel reference from same image -> proxy, not production eligible
3. Explicit legacy pixel profile -> proxy, demo-only, never automatic
4. No valid reference -> NOT_DETERMINABLE (undetermined)

### Calibration mechanism used
Existing `ml/quality/calibration.py` abstraction (ArUco + manual). A physical mm profile
now REQUIRES valid calibration; without it the result is undetermined with a warning.
Pixel profiles do not require calibration but are limited/proxy status.

### Legacy profile treatment
`grain_profiles/default_rice.json` already contains `data_status: "Proxy"` and clear notes.
The `GrainProfile` dataclass now reads `data_status` and `production_eligible` from JSON.
Legacy pixel profiles return `reference_status = "limited"` (never "reliable") and
`reference_data_status = "Proxy"`, `production_eligible = False`.

### All-broken behavior
- B13 + explicit legacy profile: 12 masks, 0 whole, 12 broken, 0 undetermined, 100% broken,
  reference_data_status=Proxy, production_eligible=False
- B13 with no reference: 12 masks, 0 whole, 0 broken, 12 undetermined, broken%=None,
  with clear explanation "No valid whole-kernel reference available for this image."

### Mixed-image behavior
Sample-derived reference uses upper-population clustering from same-image whole-looking
grains. Does NOT use mean(all grains) or max(all grains). Requires >= 3 candidates with
CV <= 0.15 and elongation/solidity evidence.

## 2026-10-08 — Final hardening of Whole/Broken reference and measurement semantics

### Task
Harden the reference/measurement semantics so the Whole/Broken analysis is technically
defensible. Focus: calibration validity states, reference provenance, all-broken handling,
scale-invariance, documentation, and validation artifacts.

### Root cause found
The previous master task had laid the correct foundation, but calibration semantics were
still coarse:
- `calibration_status` tracked only the mode string (`aruco`, `manual`, `none`), not
  whether the calibration was actually valid for metric comparison.
- A physical mm profile could pass the "calibration exists" check even when the scale
  was outside sanity bounds or markers were invalid.
- No explicit test covered invalid/unavailable calibration states.
- Documentation did not clearly state the three reference classes or the calibration
  validity contract.

### Calibration validity states added
`ml/quality/calibration.py` now exposes three explicit validity states:
- `valid` — marker/reference detected, geometry valid, configured size valid, scale
  finite/positive, within configurable sanity bounds (`ppmm_min`/`ppmm_max`).
- `invalid` — calibration claimed but markers invalid, scale non-finite/non-positive,
  or outside sanity bounds.
- `unavailable` — no calibration reference detected.

`CalibrationResult` dataclass now includes:
- `validity: str` — one of `valid` / `invalid` / `unavailable`
- `validity_reason: str` — human-readable explanation for invalid/unavailable states
- Both are exposed via `to_dict()`.

### Reference resolver hardened
`ml/quality/geometry.py` `resolve_whole_kernel_reference` now:
- Reads `calibration_validity` from the calibration dict (defaults to `unavailable` if absent).
- For physical mm profiles, requires `calibration_validity == "valid"`. Any other validity
  state returns `undetermined` with a clear reason including the validity reason.
- Exposes `reference_calibration_validity` and `reference_calibration_validity_reason`
  in metadata.
- Pixel profiles do not require calibration but remain `production_eligible = false`
  and `reference_data_status = "Proxy"`.

### All-broken behavior preserved

## 2026-10-08 — Fix monitoring dashboard for real production log format

### Root cause
The dashboard parser assumed every log line was pure JSON (`json.loads(line)`).
Real production logs use Python's standard logging format with a prefix:

```
2026-10-08 03:07:48,214 [INFO] grain_structured: {"timestamp":"...","event":"request_started",...}
```

Because `json.loads` failed on the full line, every record was counted as
malformed, leaving the dashboard with zero records and a RED health state.

### Fix
1. **`monitoring/log_parser.py`**:
   - Added `_extract_json(line)` that finds the first `{` and parses from
     there onward.
   - Updated `_parse_line` to support both pure JSONL and logging-prefixed
     JSON.
   - Added diagnostic counters: `files_read`, `lines_read`,
     `records_loaded`, `malformed_lines`.
   - Fixed `DEFAULT_LOG_DIR` to resolve to the project `logs/` directory
     (`A:\grain\logs`) instead of `A:\logs`.
   - `AnalysisRecord` now stores `filename` and `segmentation_method`
     so the history tab works without accessing a non-existent `raw`
     attribute.

2. **`monitoring/app.py`**:
   - Added **Log Parser Diagnostics** expander showing resolved log
     directory, files read, lines read, records parsed, malformed lines,
     latest timestamp, and parser mode.
   - Fixed health status: no longer shows RED when records were
     successfully parsed.
   - Improved overview metrics to show Successful Requests, Success
     Rate, P50/P95/Max response times.
   - Ensured API failures and analysis successes are tracked
     independently (e.g., HTTP 500 after successful analysis).
   - Added `level` and `route` filters to Live Log View.
   - Respects `GRAIN_LOG_DIR` environment variable.

3. **Tests**:
   - Rewrote `tests/test_monitoring.py` with 26 regression tests
     covering real log format, request/analysis reconstruction,
     rotated files, sorting, duplicate handling, and diagnostics.
   - Updated `tests/fixtures/monitoring_sample.log` to use exact
